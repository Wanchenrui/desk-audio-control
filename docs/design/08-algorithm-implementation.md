# 后台算法实现与未测指标

v1.6.0 以 v1.5.0 为基线实现[算法交接方案](07-algorithm-brief.md)，使用 C# 5 和 .NET Framework。本次发布已编译正式版，离线回归、窗口冒烟、硬件测量和运行中的客户端升级均未执行。

## 实现入口与取舍

| 功能 | 实际路径和边界 |
| --- | --- |
| 在线判断 | 端点通知携带 ID，扫描重读受影响的端口和现有同组端口，定时整机扫描修正漏报。DevicePresence 综合 KS 插孔、蓝牙链路、PnP 父节点、接入时序、播放会话与峰值、近期手选及纠正历史。端口消失后短于 2 秒的重现不提供新的接入佐证。USB 接收器单独在线最多给出一键建议。驱动缺少观测能力时保留不确定性。 |
| 路由决策 | SwitchGuard 将共享输出上的未分类播放降为点击确认。摄像头、会议、录音、离开和占用读取失败继续阻断。规划和点击建议各自读取一份设备快照。预调音量前后都读取当前 Windows 角色和会话，角色变化时停止写入。两种可重试的 RPC 忙错误立即重读一次，持续失败时在决策原因中记录 HRESULT。DecisionRecord 的耗时使用单调时钟，以第一条通知为零点。尚未走到的写入与读回阶段留空。历史记录沿用原评分回放。 |
| 偏好反馈 | 以原有评分差作为相对胜算的先验。同一设备、场景至少有 8 次稳定执行后加入有界的保留与纠正反馈。设备在该场景的历史选择分按 14 天半衰期衰减，正负分均随时间趋近零。信任等级仍由稳定执行和纠正决定。仅本机记录参与训练。概率表示模型偏好，校准误差未测。 |
| 音量 | Comfort/ 下的 v2 样本含音量、可用的端点 dB、时间戳和日夜标志，旧格式在下一次学习时迁移。最近 16 条按 30 天半衰期折算，带日期的样本最多保留 90 天用于规划。两侧同一时段各至少 3 条有效记录才允许抬高目标。学习时可从任意数量的驱动测点中提取当前音量对应的 dB。LevelPlanner 在完整单调曲线上规划六步淡入，驱动点冲突时使用百分比。耳机继续观察十二个节拍的峰值。耳机上限可在面板调低。内容响度自动补偿留待各驱动环回取点确认。 |
| 麦克风 | 用户发起 32 kHz 单声道诊断，每 50 ms 计算能量、过零率和 24 个频带。语音筛选、工频及其谐波、削波和播放包络相关性分别参与报告。安静段污染时可顺延最多 1 秒。MicAdvisor 的语音目标为 −24 至 −16 dBFS，单次请求不超过 6 dB，并限制写入的音量步长。工频同时参考相邻频点的噪声和三个半秒窗口中的持续性。安静段可报告 400–2000 Hz 的持续单音。回声延迟搜索范围为 0–500 ms，分辨率为 50 ms。 |
| EQ | EqMatcher 按完整型号、清理后的名称和保守的词边界排序。通用 DAC 可手选，选择绑定设备和端口；同一模拟插孔更换无标识耳机仍需人工确认。EqPlanner 按强度缩放增益，按端点采样率汇总预设频响及余量。100% 优先采用目录前级，估计正增益超出余量时进一步衰减。显示的余量只覆盖这份滤波器在稳态正弦输入下的频响。 |
| 系统应用 | 采用交接方案的档 1。用户自行安装 Equalizer APO 并注册端口，DeskAudio 写入受端口 GUID 限定的 Include。原始主配置、提交中的配置清单和内容摘要用于冲突检测与还原。DeskAudio 不打包第三方程序。用户主动测量时才开启参考音和环回，保留频带统计。共享模式以外的实际覆盖、热加载和驱动取点未测。 |

## 配置与设备维护

在 `%LOCALAPPDATA%\DeskAudioControl\settings.json` 的 `Values` 对象中，`SceneConfirmMs` 控制新场景连续出现的时长，范围 0–60000，默认 `"5000"`。`SceneDwellMs` 控制当前场景的最短驻留时间，范围 0–300000，默认 `"15000"`。值使用毫秒数字字符串，重启后生效。录音、会议和摄像头保护每次都依据实时状态判断。

同一目录下可选配 UTF-8 文件 `scene-apps.json`。下面的配置将公司会议软件和播放器加入场景识别。

```json
{
  "company-meeting.exe": "会议",
  "my-player": "音乐"
}
```

进程名忽略大小写，可带 `.exe`。类别可用会议、录制、音乐、影音、游戏、专注和离开。下一次读取场景时加载更改，文件编辑期间沿用最近成功加载的映射，删除文件后恢复内置规则。将浏览器归入影音仍会对共用通信端口上的播放要求点击确认。Windows 报告录音、摄像头或专用通信端口播放时会阻断切换。仅凭浏览器进程名无法区分收听网页会议和播放视频。

两个无唯一序列号的同型号 USB 设备曾同时在线时，会按实例保存身份。只剩一台并不能确定是哪一台。若已退役另一台，希望重新按型号跨接口识别，退出该账户各桌面的 DeskAudio，在程序目录运行下列命令，将参数换成设备实际的 VID 和 PID。

```powershell
.\DeskAudio.exe --reset-usb-identity 'VID_1234&PID_ABCD'
```

命令仅清除该型号及其重复序列号的歧义标记。下次启动时使用当前设备重新识别，两个同型号再次同时接入时会重新分开。已有实例专属偏好仍按原始键保留。

## 审查中的边界条件

| 报告编号 | 代码依据及处理 |
| --- | --- |
| 1–3、5–7 | 增量扫描先合并完整端点集合，再更新接入窗口。消失不足 2 秒仅视为抖动，达到 2 秒的重现获得新的 30 秒窗口。三次快速纠正将弱佐证设备限制到仅提示。Windows 的 XLR 枚举值为 9，已有处理。蓝牙枚举结束时保存错误码。空闲扫描门返回限制在计时器取值范围内的静默间隔。 |
| 4 | 默认保存曾同时接入的同型号设备的身份歧义。设备退役后可用上面的命令按型号重置。 |
| 8–11 | 瞬态 COM 忙错误重读一次，仍读取失败时阻断切换并留下错误码。用户可扩展应用分类和调整场景时序。14 天半衰期同时作用于正负选择分，即使曾经达到限分也会逐渐衰减。 |
| 12、15 | v1 将已保存的评分差单调映射为概率，保留 v0 的分差门槛。路由事务沿用对原始角色、写入读回和还原失败的检查。 |
| 13、14 | 路由计划显式接收本次设备快照，预调前后都重新读取角色，写入阶段还会检查事务的预期角色。 |
| 16、19 | 淡入计划定义六步音量变化和耳机共十八次峰值观察。按当前音量选择可用的实测 dB 锚点，冲突读数舍弃。 |
| 17、18、20 | 完整的增益曲线用于规划包含低音量起点在内的整段淡入。缺少端点时保留刻度回退，少于三个舒适样本时只保留或降低音量。还原动作继续检查事务所有权和当前音量。 |
| 21、22、26、27 | FFT 工作区按实例使用，每帧开始清零虚部。频带按 FFT 频点离散划分，语音电平对相邻排序样本插值。报告提示先排查嗡声再提高增益，削波仍优先降增益。 |
| 23–25 | 工频在三个半秒窗口中至少两次突出于邻频底噪才会报告。回声按播放领先输入 0–500 ms 搜索。中频单音须在至少十二个干净块的安静样本中占八成，并集中在近似同一频点。 |
| 28–31、35、36 | EQ 简称排除仅由 Pro、One 等通用词组成的名称。峰值扫描包含滤波器中心、直流和奈奎斯特频率，峰值下界为零，因此完整强度前级最大为 0 dB。环回沿用低电平探测音，有效频带数低于 12 时给出重测提示。原相对功率门槛已排除零基线，现显式筛除两次读取中的零值和非有限值。 |
| 32–34 | APO 在同目录替换主配置，原始字节已保存在状态文件中。附加指令前有换行。管理端口达到数量上限时显示具体限额，重新打开时按主配置内容判定中断事务是否提交。 |

设备发现缓存持有实例锁后再进入 USB 歧义历史锁。历史处理应保持这个方向，不能在持有历史锁时回调缓存。Windows 的插孔枚举把 3、5、6 分别定义为内部 ATAPI、光纤及其他数字接口。[Microsoft 插孔连接类型](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ksmedia/ne-ksmedia-epcxconnectiontype)

蓝牙连接位由 Windows 提供，APO 文件的 Device、Include、Channel 和 Stage 命令遵循原项目文档。[Windows 蓝牙设备信息](https://learn.microsoft.com/en-us/windows/win32/api/bluetoothapis/ns-bluetoothapis-bluetooth_device_info_struct) · [Equalizer APO 配置参考](https://sourceforge.net/p/equalizerapo/wiki/Configuration%20reference/)

## 未测清单与建议采样口径

以下是后续验收的目标和起始样本量。各项按设备类型分别报告样本数、失败数和分布。稳定执行指角色读回成功并经过至少 30 秒，后续撤销或改选通过关联记录计入纠正。

| 指标 | 建议验收口径 | 当前状态 |
| --- | --- | --- |
| 在线误判 | 每类至少 150 次人工标记的插拔、接收器断链和冷启动观测，目标低于 2% | 未测 |
| 切换耗时与打断 | 每类至少 100 次接入，报告去抖、扫描、决策、写入和读回的 P50/P95，总耗时 P50 目标低于 500 ms；另测音流中断 | 未测 |
| 稳定期纠正 | 至少 200 次稳定执行，记录 7 天窗口的关联撤销与手动改选，目标低于 5% | 未测 |
| 会议保护 | 至少 100 次已知会议、浏览器通话、纯录音和摄像头使用中的接入，目标零误切 | 未测 |
| 响度 | 各设备对至少 30 轮同一参考音对照，先确认采样点，再以独立响度计测端点内差值，目标不超过 2 LU；耳边响度需耦合腔及测量话筒 | 未测 |
| 麦克风 | 至少 200 段人工标注输入，其中至少 50 段含削波。诊断一致率目标 ≥90%，削波漏报目标为零。对可调增益用例，一次调整进入目标语音区间的目标 ≥80% | 未测 |
| EQ 识别与效果 | 至少 300 个标注名称，覆盖近似型号、常见前后缀和未知 DAC，误配目标 <1%，已知型号加常见前后缀的召回目标 ≥90%。另测注册端口及独占播放、配置冲突、满幅输入和 20 Hz 至 20 kHz 频响 | 未测 |

参考音环回比较使用 24 个频带，供判断处理链是否产生可观察变化。验证 0.1 dB 级的频响偏差需要独立的高分辨率测量。
