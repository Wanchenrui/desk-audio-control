# 策略引擎与动作层

## 策略引擎

处理分三段：硬约束，评分，仲裁。

### 硬约束（任何情况都不越过）

- 通话中不切换输出，除非设备被拔出。
- 正在录音时不改默认输入。
- 虚拟设备永不自动成为默认（对应现有的 `Virtual` 判断）。
- 用户刚手动操作过，进入静默期。
- 同一流向 30 秒内最多自动切换一次。

### 评分

总分 = 偏好概率 + 新近度 + 质量 + 场景适配 − 切换代价。切换代价随当前活跃会话数增加。面板上提供一个积极到保守的滑杆，由用户调权重，用户不需要理解公式。

### 四级自治

| 级别 | 行为 |
| --- | --- |
| L0 | 只提示 |
| L1 | 提示加一键执行 |
| L2 | 执行并提供撤销（默认） |
| L3 | 静默执行 |

升降级按（设备，场景）独立进行：同类动作连续多次没被撤销就升级，被撤销一次就降级。信任是挣来的。

### 解释

每次动作写入决策日志：时间、触发源、候选及得分、采用理由、结果。界面上提供为什么切换了的入口。

## 动作层

- **统一事务**：快照，执行，读回校验，失败回滚。现有 `AudioCore.Route` 已经是这个模式，要推广成通用接口，覆盖路由、音量、静音、平衡、配置应用。
- **撤销栈**：全局快捷键撤回最近一次自动动作。
- **应用级路由**：让会议软件走耳机、音乐走音箱。Windows 10 1803 起支持每应用输出设备，但接口未公开，必须做版本探测、自检和降级。

### 关于无感的诚实说明

默认设备切换时，应用的音频流会被 Windows 重建，会有短暂的间隙，量级预计在百毫秒左右，需要实测确认。前期只能做到音量淡入。真正无缝的交叉淡化要依赖自己的虚拟设备层，放在最后阶段。
