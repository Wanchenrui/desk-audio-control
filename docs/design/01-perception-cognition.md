# 感知层与认知层

## 感知层：看见一切

| 信号 | 来源 | 用途 |
| --- | --- | --- |
| 端点增删、默认变更 | IMMNotificationClient（已有） | 触发重扫 |
| 物理设备归并 | CfgMgr32 加注册表（已有 AudioDiscovery） | 同一设备的播放和录音合为一项 |
| 3.5mm 插孔插拔 | KS 插孔描述（已有 JackSense） | 识别耳机插入 |
| 音频会话 | IAudioSessionManager2 | 谁在发声，哪个进程在用话筒 |
| 实时电平与频谱 | IAudioMeterInformation（已有峰值）加环回采集 | 响度、削波、静音异常 |
| 会议态 | 话筒和摄像头占用状态、前台进程类别 | 场景识别，不读窗口内容 |
| 系统状态 | 锁屏、休眠、电源、显示器拓扑、Dock | 释放和恢复设备 |
| 蓝牙状态 | A2DP / HFP 配置、连接事件 | 避免通话音质劣化 |
| 用户纠正 | 手动切回、手动调音量 | 学习信号，价值最高 |

所有信号先进入统一的事件总线，做去抖与合并（插拔抖动 400 毫秒内合并为一次），再交给认知层。

## 认知层：理解

### 设备数字孪生

每个物理设备一份档案：

- 稳定身份：USB 序列号、容器 ID、蓝牙地址（已有）
- 能力：声道数、采样率、形态、是否有话筒、HFP 是否单声道
- 用户标注的用途
- 历史统计：使用时长、常用音量区间、掉线次数、削波次数
- 校准数据：增益偏移、EQ

### 角色推断

多证据融合：形态码（已有）、名称词典、总线类型、使用行为（例如只在夜里用、只在会议用）、用户标注。输出一个概率分布，如音箱、耳机、耳麦、会议话筒、采集卡。置信度决定要不要自动纳入日常设备。

### 场景识别

场景包括会议、音乐、影音、游戏、专注、录制、夜间、离开。先用规则初筛，再用轻量分类器（决策树或逻辑回归）。特征包括前台进程类别、话筒和摄像头占用、会话数、输出动态范围、时段。每个场景带迟滞和最短驻留时间，避免来回跳。

### 偏好模型

对每个（场景，流向）学习各设备被选中的概率，用上下文 Bandit（Thompson 采样）。先验来自现有规则，所以冷启动不会乱。手动纠正按强负反馈处理，长时间不纠正按弱正反馈处理。

### 异常检测

频繁掉线、削波、应该有声却电平全 0、采样率被应用抢占，都记为音频健康事件，进入时间线并计入设备档案。
