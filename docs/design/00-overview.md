# 总览

## 目标

让声音始终出现在对的设备上，响度对，处理链对，并且用户几乎感觉不到系统的存在。

## 设计原则

1. **无感优先，可解释，可撤销。** 每个自动动作都说得出理由，也都能一键撤回。
2. **安全护栏高于智能。** 自动动作不得造成突然的大音量，不得打断通话，不得抢在用户操作中途执行。
3. **渐进自治。** 系统按置信度和用户信任，一级一级地放权。
4. **本地优先。** 音频内容绝不落盘，也绝不上传，只留电平统计这类特征。
5. **核心零依赖。** 保持只靠系统自带 csc 就能构建这一现有优势，重功能做成可选插件。

## 分层

```
交互层    面板 · 托盘 · OSD · 命令面板 · 热键/宏键盘 · CLI/管道 API · MCP
   ↕
编排层    场景引擎 · 策略引擎 · 动作事务与撤销 · 解释器 · 决策日志
   ↕
认知层    设备数字孪生 · 角色推断 · 场景识别 · 偏好模型 · 异常检测
调优层    响度匹配 · 柔着陆 · EQ 库 · 麦克风医生 · 降噪 · 房间校正
   ↕
感知层    端点事件 · 设备图 · 插孔感知 · 会话图 · 电平频谱 · 上下文信号
   ↕
适配层    MMDevice · WASAPI · IPolicyConfig · CfgMgr32 · KS · 电源/显示/会话事件
```

## 闭环

感知 → 认知 → 决策 → 动作 → 用户反馈 → 学习。用户的每次手动纠正都回流成学习信号，这是整个系统最有价值的数据。

## 现状与差距

| 层 | 现有 | 缺口 |
| --- | --- | --- |
| 适配 | AudioCore（路由、音量、静音、平衡、峰值） | 缓存 COM 对象，拆分职责 |
| 感知 | EndpointEvents、AudioDiscovery、JackSense | 会话图、频谱、上下文信号 |
| 认知 | SmartPolicy 的规则 | 数字孪生、场景识别、偏好学习 |
| 编排 | 无 | 策略引擎、事务与撤销、决策日志 |
| 交互 | 面板、托盘、两个热键 | OSD、命令面板、时间线、开放接口 |
