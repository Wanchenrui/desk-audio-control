# 维护约定

## 构建与测试

- 构建：在工程根目录运行 `.\Build.ps1`，用 Windows 自带的 .NET Framework 4.x 编译器生成 `DeskAudio.exe`。该编译器只支持 C# 5，新代码不要用 `?.`、字符串插值和表达式体成员。
- 离线回归使用 `.\tests\Run.ps1`，涵盖设备发现、用途策略、端点缓存、扫描调度、P1 事务与存储、P2 场景/评分/信任、跨流恢复和更新检查。
- 在 Windows 交互桌面运行 `.\tests\PanelSmoke.ps1` 可测窗口消息循环、后台扫描、自动切换与撤销，并读取本机端点。加 `-Screenshots <目录>` 可输出两种主题及 100% / 125% 布局截图。测试使用临时配置与模拟路由写入。
- 新增源文件要同时加进 `Build.ps1`。

## 提交约定

- 一次提交只做一件事，标题用英文祈使句，与现有历史一致。
- 仓库内文本一律存 LF，已配置 `core.autocrlf=true`，不要提交整文件的换行改动。
- 未经确认不推送远程。

## 变更门槛

- 改 `AudioCore`、`AudioDiscovery`、`SmartPolicy`：先补离线测试，再改实现。
- 改界面：在浅色和深色两种主题、100% 与 125% 以上缩放下各看一遍真实窗口。
- 验证界面时，用独立互斥量的临时副本运行，不要覆盖或结束用户正在运行的实例。

## 发布

- 版本号取自程序集版本（`AssemblyInfo.cs`）。
- 发布用三段式标签，例如 `v1.0.0`，Release 资产必须叫 `DeskAudio.exe`。更新检查据此判断新版本，不满足就会报错。
- v1.2 起，发布资产需有 GitHub 提供的 SHA-256 digest。先上传到草稿 Release，再公开并从资产 API 回读核对大小、摘要和程序集版本。私有下载沿用更新页授权的 Contents 只读凭据。
- 构建脚本将独立更新组件嵌入单个 EXE。更新组件等待旧进程退出后原位替换；新版首次进入窗口消息循环时，通过 `--updated <任务 ID>` 回报启动成功。后续版本应保留该握手，以便上一版本的更新组件确认启动并清理备份。
- `tests/Run.ps1` 包含应用内更新回归与 Windows 进程交接测试。可单独运行 `tests/UpdateProcess.ps1`，在含空格和中文的临时目录验证安装、同路径重启、失败恢复和损坏包拒绝。
